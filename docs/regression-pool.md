# 错题池（regression pool）

> 把**已经出现过的问题**变成可重跑的用例。目的有两个：旧问题不能被后来的检查项"改回去"（漏报），正确文本也不能被新检查项误伤（误报）。
>
> 用例定义在 `tools/tests/regression_pool.py`，执行者是 `tools/tests/test_regression_pool.py`。

## 怎么跑

```bash
cd tools
py -3.11 -m unittest discover -s tests -p "test_regression_pool.py" -v
```

或者直接跑 `py -3.11 tools/scripts/selfcheck.py` —— 它的第一步就是 `unittest discover`，错题池随全部单测一起跑，不需要单独配期望值。

## 两种用例，含义不同

| 类型 | 含义 | 改动时该怎么办 |
|---|---|---|
| `auto` | 规范已经把这条定死，当前行为就是应有行为 | 用例失败＝回归，先修代码；若确属规范变更，同时改规范、本用例与本文件 |
| `locked` | 当前行为是**已知偏差、启发式误报或实现怪癖**，不是规范已满足 | 用例失败说明行为变了；这时要判断是"修好了"还是"改坏了"，再同步更新期望值、规范与本文档 |

`locked` 的用例不是"通过的假用例"。它锁的是**今天的事实**，注释里写明规范要什么、实现做什么、为什么不在这里改。把 `locked` 改成 `auto`，意味着那条偏差已经被处理掉。

## 八条 locked 用例说明

1. **RP-03 / RP-04（教材、讲座标 S 只报 warn）**
   规范 R7 的「工具」一段写「命中教材词表却标 A 或 S → error」，实现把「教材」「讲座」放在 `WEAK_POPULAR`，只报 warn。这是规范与实现的既有不一致，本次只登记，不改判定逻辑。
2. **RP-06（R2 的正例被报 warn）**
   规范 R2 的正例正是这条双定位写法；实现的 `GRADE_TRANSLATION` 只检查出处里有没有字面「原文」，没有就 warn。规范说合规、工具说可疑——锁在这里，避免有人把它当误报直接删掉。
3. **RP-08（同一引用键的启发式误报）**
   `citation_key` 只取前三个逗号段，第四段的「卷一」「校记」被截掉，于是同书不同层次被归成同一键。§4.2 要求"把差异写进出处"，但写进去也拆不开。告警文案已含"请人工确认"，故保留。
4. **RP-10（嵌套错误的行列号不指向整篇文档）**
   内层错误的行/列是相对 locator 子串算的，不是相对整篇。用例只断言代码与级别，不断言位置。
5. **RP-11（跨行标记被判未闭合）**
   解析器遇 `\n` 即放弃配对，同一个跨行标记会报两条错，文案却说"缺少〕"。规范 R13 只规定挂载位置，未明文要求单行，属实现比规范更严。
6. **RP-12（半角竖线被静默接受）**
   `parser.BARS` 同时接受 `｜` 与 `|`，也没有针对半角竖线的检查（`TAG_HALFWIDTH` 只管半角方括号）。规范 §1 要求全角。若将来新增 `TAG_HALF_BAR`，本用例会失败——那正是提醒同步改规范与本文档的信号。
7. **RP-13（只有年份不报）**
   `LOCATOR_NO_LOCATION` 只看出处里有没有数字。「1684」算数字，于是通过；"年份够不够定位"是史学判断，工具做不到。

## 不能自动断言的项

这些没有对应的可执行用例，只在 `SEMANTIC_ONLY` 里登记，**不要**为它们硬凑能通过的用例：

| ID | 事项 | 为什么不能自动判断 |
|---|---|---|
| SP-01 | 「来源不明」标 U（2026-11-16 已裁决，`docs/method*.md:26` 与 R8(c) 已对齐） | 裁决本身是语义判断；工具看不出作者是"不知道"还是"知道但没写" |
| SP-02 | 只有年份是否构成足够定位 | 取决于所引文献实际情况，属史学判断（RP-13 只锁"当前不报"） |
| SP-03 | 点校本的正文与点校层是否真的分属两层 | 要看原书；RP-08 只锁"会告警、须人工确认" |
| SP-04 | `corpus/` 前缀解析 | v0.2 未实现，v0.1 无相关代码，构造不出用例 |
| SP-05 | 标了 F 是否同时给出它指向的 A 或 S | 需要读正文语义，不是标记层的性质 |

## 加用例的规矩

1. 一次缺陷、一条用例；ID 顺延，不复用。
2. 先写清"针对哪条规则、期望什么结果"，再跑一遍确认真实行为——**期望值必须来自实跑**，不能凭规范推断。
3. 如果现实行为与规范不一致，用例标 `locked`，注释写清两边分别是什么，并在上面两节里登记；不要把它写成 `auto` 假装通过。
4. 语义类问题进 `SEMANTIC_ONLY`，不进 `CASES`。
5. 新增或修改用例后，`selfcheck.py` 必须整体 PASS；`RELEASE-CHECKLIST.md` §0 的勾选以它为准。
