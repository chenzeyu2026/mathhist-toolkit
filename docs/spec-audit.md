## 0. 为什么这些内容不放进规范正文

`spec/evidence-tags.md` 这次新增了三节：§1.5（情境有效性）、§2 末（条款分类与关键度）、§5.1（报数口径）。它们都留在了正文。被拆到这里的是三样东西：

1. **逐条数值表**——随规则集版本漂移，对写作者零信息量；
2. **Alloy 6.2.0 第二实现方案**——维护者工具，写进规范会让读者以为用这个零依赖工具包需要先装 Alloy；
3. **复现方法与其缺口**——属于工程事项。

判断依据：规范正文回答"我该怎么标"，本文回答"规则集本身还站得住吗"。两者读者不同。

## 1. 有限域与 §1.5 的对应

规范 §1.5 定义了六个维度。把它们展开成笛卡尔积，再按 E1–E6 压缩：

| 阶段 | 组合数 | 说明 |
|---|---|---|
| 六维笛卡尔积 | 1620 | 15 载体 × 3 定位 × 3 层数 × 2 原文页码 × 2 中转者 × 3 阻断 |
| 经 E1 剔除 | −1008 | 非二手载体却带非零转引层数 |
| 经 E3 剔除 | −168 | 非二手载体却称"有线索未取原件" |
| 经 E4 剔除 | −68 | 阻断为"缺页"却"版次+页码齐全" |
| 剔除后余 | 376 | 情境都成立 |
| 经 E2 / E5 / E6 归并 | 168（宽）/ 90（窄） | 宽：维度有指称即算活；窄：只算被规则读取的维度 |

15 类载体里的"点校本（未分层）"是 v0 编码的产物：R2 判点校本为 `S`、R3 判点校本正文为 `A`，不分层时两者对同一载体给出相反判定。规范 §1.5 已要求写作时写明正文或校记；写明后为 14 类。v0.1 编码刻意保留 15 类，是为了把这个歧义显式暴露出来；v1 基线按 14 类计算。

注：168 / 90 是**上界**。同版式影印的"原文页码"在语义上与原刊同为冗余，但审计在归并时只把原刊视为该字段无指称，未合并影印，故真实值略低（未实测）。规范 §1.5 的 E6 已按此口径写明。

v1 基线（2026-11-16 采纳）把未分层的"点校本"从载体表移除（§1.5 已要求写明正文或校记），空间为 1512 → 356 → **160（宽）/ 86（窄）**。168 / 90 保留作 v0.1 编码的对照值，不再作为对外基线。

## 2. 逐条关键度

口径见规范 §2 末。以下为实测值：v0.1 编码的空间是 168（宽）/ 90（窄），已采纳的 v1 基线是 160（宽）/ 86（窄）。

**现行 v0.1 条款**（空间 168：唯一 118 / 不定 16 / 冲突 34；空间 90：唯一 64 / 不定 8 / 冲突 18）

| 条款 | 关键度（宽） | 参与行数（宽） | 关键度（窄） | 参与行数（窄） |
|---|---|---|---|---|
| R1 / R9 | 24 | 36 | 12 | 20 |
| R2 | 9 | 40 | 5 | 24 |
| R3 | 16 | 28 | 8 | 16 |
| R5 | 61 | 92 | 31 | 50 |
| R8 | 27 | 109 | 14 | 59 |
| R7 | 19 | 168 | 10 | 90 |

v0.1 没有空转条款：六条的关键度均大于 0。R5 独大（宽口径 92 行中 61 行因它而变），冲突的主要来源是它与 R2/R3 在"译本/点校本"上的重叠。

**已采纳的 v1 基线**（空间 160：全部唯一；空间 86：全部唯一）

| 条款 | 关键度（宽） | 参与行数（宽） | 关键度（窄） | 参与行数（窄） |
|---|---|---|---|---|
| R1 / R9 | 12 | 60 | 6 | 32 |
| R2 | 0 | 32 | 0 | 20 |
| R3 | 0 | 20 | 0 | 12 |
| R5 | 50 | 116 | 25 | 62 |
| R8 | 0 | 58 | 0 | 32 |
| S-6（占位→U） | 2 | 35 | 1 | 19 |
| R7 | 6 | 160 | 3 | 86 |

v1 里 R2、R3、R8 是**被吸收**，不是空转：它们仍参与 32 / 20 / 58 行，但限制已被 R5 蕴含。按规范 §2 末第 2 条，这三条应**保留并标注"被 R5 吸收"**，不得删除——一旦 R5 收缩，它们会立刻变回关键条款。

> 命名注意：内核里那一条标作 `R6/S-6`，实际内容是 S-6（占位出处一律判 `U`），与规范的 R6（冲突处理，程序类）不是同一条。此处按 S-6 记。

## 3. 收敛口径

| 版本 | 载体 | 笛卡尔积 → 剔除后 | 宽口径 | 窄口径 | 冲突 | 不定 |
|---|---|---|---|---|---|---|
| v0.1 编码（保留作对照） | 15 | 1620 → 376 | 168 | 90 | 34 / 18（20.2% / 20.0%） | 16 / 8（9.5% / 8.9%） |
| **v1 基线（2026-11-16 采纳）** | 14 | 1512 → 356 | **160** | **86** | 0 / 0（0%） | 0 / 0（0%） |

报数只用率、不用条数；宽窄两个口径都给；冲突与不定同时报。理由与规范 §5.1 同。

**160 与 86 是当前基线，可以对外引用**，但必须同时给出四件事：宽/窄两个口径、14 类载体（已剔除未分层的"点校本"）、1512 → 356 的两步剔除、以及分母本身（160 / 86）。只写「零冲突」而不给分母，仍然不可引用——数字没变，是它没交代在哪个空间上成立。

v0.1 的 168 / 90 留在第一行，用途是回答"v1 到底改掉了多少"：宽口径冲突率 20.2% → 0%，窄口径 20.0% → 0%。

规范正文的条款文字（R2 译本、R3 点校本、R8 的 `U` 情形）与 v1 的 S-1–S-6 尚有措辞差异，下一版规范同步；在此之前，条款以 §2 的 v1 表为准，数字以本表为准。

§4 的 Alloy 第二实现尚未执行。引用这两个数字时，限定为"本实现对 v1 基线的判定结果"，不要写成"规则集已被独立验证"。

## 4. Alloy 6.2.0：独立第二实现

### 用途

换一套机制把同一套规则重写一遍，用来暴露**编码错误**，不是用来验证历史判断。

有实际依据：第一版 Python 判定核里，一条规则写了 `s = ALL` 再 `s &= {...}`，就地改写了全局集合，导致整批结果伪造性地全部冲突。这类错误自然语言规范读十遍也看不出来，换一种表达（关系代数 + 自动枚举反例）就会立刻冒出来。同样的风险在于：把 R1–R13 翻成判定核这一步本身没有第二个人核对过。

### 触发条件

**只有当"0 冲突"要写进对外文档、当作证据时，才实际执行。** 平时不进 CI，不写进发布版规范，不作为运行时依赖。

具体来说，下列任一情形触发：

- 要把"规则集无冲突"写进 README、发布说明、对外报告或论文；
- 规则集发生结构改动（新增维度、删除条款、改变条款分类）；
- 有人对某条冲突结论提出异议，而 Python 实现无法自证不是编码错误。

### 做法与边界

- 六个维度写成 `sig`，等级写成单值关系，每条判定类条款写成一个 `pred`，E1–E6 写成 `fact`。所有 `fact` 都是显式的：Alloy 不知道"载体决定哪些轴有意义"，必须把 §1.5 的六条逐条译进去，否则枚举出来的反例一半是 E1–E6 的违反。
- `run` 命令求"存在一个情境，满足所有 pred 且等级集合为空"——有解即冲突，实例本身就是人类可读的反例。
- 规模：每条条款约 5–10 行，六个判定核约 60 行。Alloy 6.2.0 需要 JVM，这是它不能进 CI 的现实原因，也是它不能进规范正文的原因。
- **边界**：Alloy 只能证明"这套规则的编码自洽"，不能证明 R1–R13 符合史学实践。两个实现一致，排除的是翻译错误，不是规范本身的错误。

### 不做的事

- 不把 Alloy 加入 `tools/` 依赖，不改 `pyproject.toml`；
- 不在 README 的快速上手路径里出现 Alloy；
- 不追求 Alloy 版与 Python 版逐行同构——允许写法不同，只要求两边的判定结果在同一情境集上逐行相同。

## 5. 复现方法

判定核（`grading_kernel.py`）、域审计（`audit_domain.py`）、关键度计算（`criticality.py`）都在 [`tools/audit/`](../tools/audit)，零依赖、随仓库发布，不再是工作区外的临时文件。

运行（任选其一）：

```bash
py -3.11 -m tools.audit              # 仓库根：三节全跑
py -3.11 -m audit criticality        # cwd = tools/：只跑一节
```

`all` 之外可选 `kernel` / `domain` / `criticality`。三节分别输出：

- **`kernel`**：v0 与 v1 各自的原始有效配置数、冲突条数、不定条数，并按"哪几条规则同时说话"分组列出反例（含每条规则的允许集合）。
- **`domain`**：六维笛卡尔积如何被 C1/P1/P2（即 §1.5 的 E1/E3/E4）剔除（v0：1620 → 376；v1：1512 → 356）；宽、窄两套口径去重后的情境数（v0：168 / 90；v1：160 / 86）；去重空间上重算的唯一/不定/冲突；空转与关键度汇总；S-12 敏感度；判定签名分布。
- **`criticality`**：宽口径与窄口径各一张表，逐条给出"删掉该规则后判定改变的情境数"（v1 宽口径：R1/R9 12、R5 50、S-6 2、R7 6，R2/R3/R8 为 0）。

输出是纯文本，只写标准输出：不写文件、不联网、不依赖第三方包。基线数字由 `tools/tests/test_audit.py` 锁定（v0 的 168/90/34/16 与 v1 的 160/86/0/0、14 类载体），所以本节数字与脚本实跑一致，不需要人工抄录，也不存在"文档写一套、脚本跑一套"的分叉。

复现步骤（对应 `domain` 各节）：

1. 展开六维笛卡尔积 → 1620；v1 去掉未分层的点校本，为 1512；
2. 按 C1/P1/P2 剔剩 376（v1：356）；
3. 按 E2/E5/E6 去重：v0 得 168 / 90，v1 得 160 / 86；
4. 对每个情境求各条款允许集合的交集：空集记冲突，多值记不定，单值记唯一；
5. 逐条删除条款重算，统计判定改变的行数，得关键度。
